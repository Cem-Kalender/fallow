The project page with solo sessions (revised on 2026-11-03: the assistant is the project's only conversation). The left column and the top bar stay as they are. The middle column is the assistant, with a dropdown of its sessions on top; there are no tabs. You discuss fixes and features with it; when a feature has been discussed enough, it suggests making it one, and the lead takes over in the feature's spec session. The lead works only behind features. Each solo session works in its own worktree, on its own branch started from your branch, so several can be open at once; your project folder is not touched. Fallow commits every turn on the session's branch, so a turn can be undone. Merging, pushing or opening a pull request: you ask the assistant, and Fallow shows what it sees happen to your branches.

1 · Discussing a feature with the assistant

The assistant suggests a feature; you check the brief and confirm

You talk a feature through with the assistant as with a colleague who knows the code. When it has been discussed enough, the assistant suggests making it a feature, with a title and a brief of what was settled (or you type /feature). Nothing starts until you confirm. Clicking "Make this a feature…" opens the confirmation in the middle of the screen, over the page. In it you can edit the title and the brief, and pick the lead (your project's default is preset).

2 · Coding with the assistant

The session dropdown; each turn its own commit, with "Undo this turn"; a command asked; a screenshot, the web, a message waiting

Clicking the session's name (shown open here) lists the project's solo sessions: the open one ticked, each named after its first message (renamed in its header), a dot while its assistant works, the number of its changes; + New session starts one from your branch as it is now. Picking one opens it. At the bottom: closed sessions, and the project conversations with the lead held before this change, readable. The header names the session's branch and where it started. A command that changes your folder, such as a merge, is always asked first, naming what is uncommitted there. In the conversation: a pasted screenshot goes to the assistant with the message; its work shows as in a loop, also what it looks up on the web; under each turn, what it changed and Undo this turn. A message typed while it works waits above the box and is sent when the turn ends.

4 · Files, while a session is open

The tree is the session's worktree, its changes marked; a file opens beside the conversation

While a session is open, the Files tab shows the open session's worktree and marks what the session changed: M changed, A new, the number of changes on a folder. A file opens in the middle and the conversation moves beside it on the right, so you see the file and the assistant at work together. A changed file opens on its changes; "Whole file" shows all of it. Read-only, as in 009: the code is changed by the assistant, or by you in your editor (Fallow commits your edits as yours before the next turn). A feature's spec session shows a file beside its conversation the same way.
