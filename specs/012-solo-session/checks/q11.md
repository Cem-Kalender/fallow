## Found and fixed

1. **A squash written in PowerShell was not recognised** (R-10, R-11). On Windows the assistant
   wrote `$p = "<folder>"; git -C $p merge --squash <branch>; if ($?) { git -C $p commit … }`.
   - **Why:** Fallow read `-C $p` literally, and the line's `if (…) { … }` made the parser give up.
     So the commit on `main` was put down to "outside Fallow", the base did not move, and the
     session said "main moved … ask the assistant to bring the branch up to date".
   - **Fix:** `src/studio/refwatch.rs` now follows the line's own variable assignments, and
     PowerShell's `if`/`else` blocks. This parser only says which refs a command moves; the command
     judge is unchanged.
2. **`git worktree list` was asked "adds, moves or removes worktrees".** It only lists. Fixed in
   `src/studio/judge.rs`; the other `worktree` forms keep the reason. In "Ask for commands" mode it
   is still asked, like every command.
3. **A refused read was shown as read.** After `.env` was denied, the turn still said
   "Read .env · …". Fixed in `src/service/web/app.js` (`filesRead` leaves out refused reads).
4. **The dashboard said "No features yet: open a project and talk with the lead"**, but the
   project conversation was retired in Phase 8. It now points to + New feature or a session with
   the assistant.
