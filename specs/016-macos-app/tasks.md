# Tasks: Fallow as a desktop app on macOS, released on GitHub

**Input**: Design documents from `specs/016-macos-app/` (spec FR-001 to FR-034, plan, research
M-1 to M-23, data-model, contracts/window-macos.md and cli-macos.md, quickstart Q1 to Q11). The
spikes show working code: `spikes/016-macos/window/src/main.rs` (`wry` on an `NSWindow`, the custom
scheme, `_close`, the hidden-page preferences, physical footprint by responsible pid) and
`spikes/016-macos/notify/main.swift` (provisional notifications).

**Tests**: the spec asks for CI checks (SC-003 to SC-008, the signature, the per-user install, the
budgets), so tests are included.

**Build and test** on the engineer's Mac: run `. "$HOME/.cargo/env"` first (cargo is not on the
shell's `PATH`). A service started for a check uses a short throwaway `HOME` (for example
`/tmp/f016`): the socket path must stay under 104 bytes. Never touch the engineer's own data
folder. Windows behaviour must not change except where a task says "both platforms"; Linux keeps
the browser page.

**WebKit SPI** (research M-18): `_close`, `_setPageVisibilityBasedProcessSuppressionEnabled:` and
`_setHiddenPageDOMTimerThrottlingEnabled:` are each called only after `respondsToSelector:`; a
missing one is logged once by the service and never crashes it.
